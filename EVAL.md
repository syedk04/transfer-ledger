# Evaluation: 12 real Premier League transfers

Ran the full pipeline (XGBoost valuation + SHAP explanation, season 2025 - the model's held-out test season) against 12 real, well-known players, generated by `scripts/run_eval.py`. Not a cherry-picked easy set: it deliberately includes the README's own documented largest-error names (Saliba, Rice, Caicedo, Saka, Isak) alongside other prominent players, so the worst cases are visible here too, not hidden.

## What this evaluates for real, and what it doesn't

Model accuracy (predicted vs. actual EUR) and SHAP availability are checked against the real trained XGBoost model and the real dataset - no external API needed for either, so these numbers are genuine. **News relevance/hallucination-checking and confidence-level calibration are NOT evaluated below** - this build environment has no live `GROQ_API_KEY` or `NEWSDATA_API_KEY` configured, and checking whether the agent's cited news is real or its confidence level is reasonable requires the agent to actually run. Faking those results would be worse than admitting the gap. To fill them in: add both keys to `.env` and re-run `python -m scripts.run_eval` - each row's `agent_note` column will then say whether the live agent ran and point at what to check (does `news_context` cite real, relevant articles; is `confidence`/`confidence_reasoning` reasonable given how far off the prediction was).

## Honest failure cases

- The model's largest absolute errors here are concentrated in the same elite players the README's Limitations section already identifies (Haaland's actual value is well above what stats alone predict) - this sample reconfirms that pattern rather than finding a new one: the model is measurably worse at pricing stars than squad players, and star-heavy samples like this one will always show a higher MAE than the full test season.
- **Two distinct, genuine reasons a lookup can fail**, both surfaced by this exact run rather than hypothesized: (1) accent/diacritic mismatch - `find_player_row`'s substring match is plain case-insensitive `str.contains`, not accent-folding, so querying "Moises Caicedo" or "Martin Odegaard" fails to match the dataset's actual `Moisés Caicedo` / `Martin Ødegaard` entries. This is a real, fixable gap in the matcher (an accent-folding normalization step), not a data problem. (2) a genuinely absent season - Kevin De Bruyne has no 2025 row because he actually left the Premier League for Napoli ahead of the 2025-26 season; the dataset is correct, the query is simply asking about a player who isn't in scope for that season anymore. `find_player_row`'s error message already distinguishes this case (it lists the seasons that ARE available for a matched name) from a true no-match.
