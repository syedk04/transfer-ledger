Yes, mostly — a plain regression on goals, assists, minutes and age explains most of the variance in Premier League valuations. What it can't explain is exactly the players you'd expect: the ones the market prices on reputation, not output.

Method, in brief

Three decisions that made the difference

Target transform

Predict log(value), not value

Market values are wildly right-skewed — most squad players sit under €15M while a handful of superstars sit at €150–200M. Fit directly on euros and a model spends all its effort on the outliers. Training on log1p(value) makes a proportional miss cost the same everywhere on the scale, then expm1 inverts it back to euros for reporting.

Split strategy

Split by season, not row

The same player appears across multiple seasons with highly autocorrelated value. A random split would let the model see Saka-2023 while being tested on Saka-2024 — effectively memorizing players instead of learning the stats→value relationship. Training on 2022–2024 and testing on 2025 alone mimics forecasting a season no one has seen the outcome of yet.

Non-linear age

A parabola, not a slope

Value rises through a player's early twenties, peaks, then declines — no single linear coefficient can represent a peak. Adding age² as a second feature lets a linear model fit that curve directly: the fitted Ridge coefficients come out +2.7 on age and −4.3 on age², the rise-then-fall shape confirmed in the data itself.

Honest scope

What "started" actually means

The source data has no starting-lineup flag, only minutes played. Rather than fake a "games started" feature off a minutes threshold, it was dropped in favor of minutes played and per-90 rates — real signal instead of a plausible-looking proxy.

Model comparison

Regularization barely mattered — the tree didn't win

Ridge's cross-validated α landed at 0.1 — light regularization, because plain OLS wasn't overfitting much to begin with. The Random Forest, included purely as a linearity check, did not beat the linear models here: with age² already handling the main non-linearity and only 1,465 training rows, the forest had little non-linear structure left to exploit and no tuning to guard against overfitting.

Honest limitations

What this model can and can't tell you

Where a linear model is the wrong tool

Value isn't a smooth additive function of stats — it has thresholds and interactions no linear model represents: one wonder-goal against a rival can move a valuation more than a season of solid-but-unspectacular numbers, and a young player's resale/potential value depends on stats this dataset doesn't have. The Random Forest exists specifically to price that cost.

Cost measured here: R² 0.603 (forest) vs 0.624 (Ridge) — small, not zero.

Collinear features, named

appearances ↔ minutes_played (r=0.89) are nearly redundant. goals ↔ goals_per_90 (r=0.75) share a numerator by construction. age ↔ age² (r=1.00) is intentional collinearity — a polynomial term, not an accident. This is exactly why the coefficient chart reads Ridge, not plain OLS.

Why age isn't linear, and the fix

Value rises through a player's mid-twenties, peaks, then declines. A single linear age coefficient forces one constant slope across a 17-year-old prospect and a 34-year-old veteran — it can't represent a peak. Adding age² lets the model fit a curve instead of a line.

Fitted signs confirm it: age +2.7, age² −4.3

What no stats column can capture

Contract length, agent leverage, club wealth, transfer hype, injury history, international reputation, resale value for young players — none of it is in this dataset. The evidence for how much that matters is in the charts: predictions track tightly under ~€30M, and nearly every large miss is an elite player whose stats are good but whose price carries a reputation premium on top.

Overall MAE €10.8M; worst individual misses reach €70–98M, concentrated in a handful of stars.
Run it yourself

The full pipeline, five commands

# download + cache raw CSVs, then build the model
$ pip install -r requirements.txt
$ python -m src.fetch
$ python -m src.build_dataset
$ python -m src.train
$ python -m src.visualize

# look up any player
$ python -m src.predict "Bukayo Saka" --season 2024
